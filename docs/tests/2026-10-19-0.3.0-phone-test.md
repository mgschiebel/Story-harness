### Steps and results

1. **Attach and clone.** Attached `mgschiebel/Skaldsaga-test` with push access. The tool resolved it to `mgschiebel/skaldsaga-test`. Shallow clone succeeded at `b1deb8f`. The repo has `.claude`, `.harness`, `spec`, `manuscript`, `reviews` and `style-guide` as expected.

2. **Was the hook line in context?** No. "This folder is a Skaldsaga project" did not appear at session start. The session started in `/home/claude`, which has no `.harness`.
3. **Hook config (plugin `hooks/hooks.json`).** `SessionStart`, matcher `startup|resume|clear`, command `sh ${CLAUDE_PLUGIN_ROOT}/scripts/skaldsaga hook session-start`, timeout 10s. In hook mode the launcher is fully quiet: any failure exits 0 with no output, so a failure and a "not a Skaldsaga folder" result look the same from outside.

6. **Meter, by hand.** `sh …/scripts/skaldsaga meter statusline` run from the repo root printed `Skaldsaga`, exit 0. The absolute plugin path committed in `.claude/settings.json` (run 1, commit `ca500b5`) still resolves in this session, because the synced plugin ID was the same as in run 1.

### Conclusions

- **The hook works, but its folder check is too narrow.** It decides from the payload's `cwd` only, ignores the process folder, and accepts only an exact match: `.harness` must be directly in `cwd`. It doesn't look one level down (where cloud sessions put attached repos) or upward (subfolders of a story).
- **In cloud sessions the hook will never fire.** The session always starts at `/home/claude` and repos are always one level down. The skill's promise that the hook "will run next session" is wrong for this environment.
- **The skill and the hook use different rules.** Skill step 0 handles "the story repo is one level down." The hook doesn't. They should share one folder lookup.
- **Project settings in the repo aren't loaded either.** The meter's `statusLine` lives in the repo's `.claude/settings.json`. Claude Code reads project settings from the session's project root, which here is `/home/claude`, so the status line was never set up. This likely explains run 1 issue 4 (meter always `unknown`), separate from the absolute-path problem.

## Issues and observations

1. **The meter settings file is left untracked by setup (issue).** `init` writes `.claude/settings.json` but doesn't include it in `commit_paths`, so the folder isn't clean after setup. In environments with a "commit everything" stop hook, the user gets prompted about it.
   - The file holds an absolute, machine-specific plugin path. Committing it (as done in this run) means the meter command won't resolve on another machine or in another session whose plugin sync ID differs.
   - **Consider:** a portable meter command (for example, relative to `$CLAUDE_PLUGIN_ROOT` or resolved at runtime), or writing to `.claude/settings.local.json`, or deliberately ignoring the file and documenting that.
2. **Empty repo clone.** The skill handled a repo with no commits fine. Only the clone helper's `rev-parse HEAD` check failed, which is outside Skaldsaga.
3. **Session-start hook is silent when the story folder isn't the session root (issue, confirmed in run 2).** See "Run 2". Repo-attached cloud sessions always start one level above the repo, so the hook never fires there.
   - **Consider:** have the hook search for `.harness` the same way skill step 0 does: payload `cwd` first, then its direct child folders (one level down), then parent folders up to the filesystem or git root. Also check `CLAUDE_PROJECT_DIR` when it's set. If a story folder is found away from the session root, say so in the context line, for example "Skaldsaga project found at `skaldsaga-test/`".
   - **Consider:** a debug switch (for example `SKALDSAGA_HOOK_DEBUG=1`) that writes why the hook stayed silent to stderr or to a log file. The launcher's quiet mode currently hides launcher failures and "no project here" alike.
   - **Consider:** correcting the skill's summary text. It shouldn't promise the hook runs "next session" when the story folder isn't the session root.
4. **Meter** never produced a reading (`unknown`) in run 1. Run 2 found the likely cause: the repo's `.claude/settings.json` isn't loaded when the session root is the parent folder (see Run 2 conclusions). The status line command works when run by hand. It's still unconfirmed whether the mobile app shows a status line at all.
   - **Consider:** documenting that the meter needs the story folder to be the session root, or making the `meter check` path not depend on the status line.
5. **Attached repos aren't registered as a project root (environment, new in run 2).** The clone helper refers to a `register_repo_root` tool, but this session didn't have one. If it had, the repo's `.claude/` settings, skills and plugins might load on the next turn. It's unclear whether that would also re-run `SessionStart` with the repo as `cwd`. Worth asking about on the platform side, but Skaldsaga shouldn't rely on it.
