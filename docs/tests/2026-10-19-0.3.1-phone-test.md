## Findings

### 1. Upgrading from 0.3.0 leaves the old tracked meter wiring in place (migration gap)
- 0.3.0 committed `.claude/settings.json` with a `statusLine` pointing at a **machine-specific absolute path** (`/root/.claude/plugins/synced/<uuid>_<uuid>/skaldsaga/scripts/skaldsaga meter statusline`).
- Run B confirms 0.3.1 **no longer does this**: a fresh setup writes only to the ignored `settings.local.json`.
- On upgrade (Run A), 0.3.1's `init` added the local wiring and reported `wired`, but it **didn't notice the old tracked entry**. The meter is now configured in two places, and the shared one carries a path that won't exist on other machines.
- **Suggestion:** when `init` finds a Skaldsaga `statusLine` in the tracked `.claude/settings.json`, either remove or move it (and include the file in `commit_paths` or `remove_paths`), or at least report it, for example with `meter.outcome: "moved"` or a `legacy_tracked_settings` flag.

### 2. `locate` returns `nothing` when the outer folder holds one repo plus any loose file
- In Run B, `/home/claude` held the one repo, `skaldsaga-test` (just `.git`, not yet set up), plus this report file and dotfolders. `locate` returned `nothing` instead of `candidate`.
- Reproduced in a scratch folder:

  | Outer folder contains | `locate` result |
  |---|---|
  | One git repo (empty, or with a commit) | `candidate` |
  | The same, plus a hidden folder | `candidate` |
  | The same, plus one loose file (`notes.md`) | `nothing` |

- This matches the skill's wording ("holds only one git repository"), so it's arguably by design. But one stray file in a home or workspace folder silently turns off detection. In cloud sessions the outer folder is the user's workspace, where loose files are common.
- **Suggestion:** consider ignoring loose files (or at least common ones like `*.md` and `*.txt`) when counting, and count only subfolders that are git repositories.

### 3. Commit message is cut off mid-word (cosmetic)
- The `commit` message for `pr-demstart` ends "...after she cros...". The cut lands in the middle of "crosses".
- **Suggestion:** truncate at a word boundary.

### 4. The session-start hook didn't fire (expected; needs a re-test)
- The session started in `/home/claude` before the repo was cloned, so the hook had nothing to detect, which the skill says is normal.
- **Re-test:** start a new session in `skaldsaga-test` or the folder just above it, and confirm the "Skaldsaga project" line appears.
