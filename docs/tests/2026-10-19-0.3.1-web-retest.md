# Skaldsaga 0.3.1 re-test: results and handover to development

**Date:** 2026-10-19 · **Build under test:** Skaldsaga 0.3.1 (synced marketplace) · **Environment:** claude.ai/code cloud session, repo `mgschiebel/skaldsaga-test`
**Feeds:** release 0.3.2 · **Raw output of run 1:** `skaldsaga-0.3.1-retest-report.md` (in `mgschiebel/skaldsaga-test`, same branch as that run)

## TL;DR

1. **The 0.3.1 hook logic is correct.** When it runs from a folder that has a story one level down, it prints the one-level-down line, and its debug messages are right. It writes nothing. If there are two candidate stories, it stays quiet. `locate` agrees with the hook in every case.
2. **The test plan's premise doesn't hold.** claude.ai/code started the session inside the repo (`/home/user/skaldsaga-test`), not at `/home/claude` with the repo one level below. So at startup the hook saw the project in its own folder and printed the root-folder line. The one-level-down path never runs at startup in this layout.
3. **The debug output isn't visible to Claude at startup.** With `SKALDSAGA_HOOK_DEBUG=1` set and confirmed in the shell, the hook's stderr didn't appear in Claude's context. The debug switch helps only when the hook is run by hand.
4. **The setup script makes a stray project.** `/home/claude/.harness` was created at session start, empty and owned by root. That is probably the setup script's `mkdir -p "$PROJECT/.harness"`. `locate` run from `/home/claude` then reports a project there that isn't real.
5. **Next round:** two orphan branches are ready, one for "no project" and one for "story one level down". See [Next round](#next-round-prepared-branches).

## Issues for 0.3.2

| # | Issue | Impact | Suggestion |
|---|---|---|---|
| 1 | In claude.ai/code, sessions start in the repo root, so the usual layout is "project here", not "one level down" | Low for the hook (that case works). High for the test plan, which assumed `/home/claude` | Rewrite the plan around the session folder (`pwd`) instead of hard-coded `/home/claude`. Use the orphan branches below to cover each case |
| 2 | Debug stderr doesn't reach Claude at startup | The debug switch can't explain a silent hook in normal use | When `SKALDSAGA_HOOK_DEBUG=1`, also emit `additionalContext` carrying the debug reason, including the no-project and "not guessing" cases, which today print nothing |
| 3 | The setup script creates `/home/claude/.harness` | A phantom project at `/home/claude`; `locate` and the hook report it if run from there | Drop that step, or derive the path from the clone location. A `.harness` without `settings.json` could also be refused as a project |
| 4 | Plan item "`CLAUDE_PROJECT_DIR` empty" | It was empty, and the hook falls back to the session folder as designed | No change; worth stating the fallback in the plan |

### Run-2 procedure (for each branch)

**Before starting the session:**
- Keep `SKALDSAGA_HOOK_DEBUG=1` set.
- Remove the setup script.
- Start the session on the branch under test.

**Checks to run:**
1. **Where it started:** `pwd; git branch --show-current; ls -A; ls -A ..`. Confirms the session started at the branch root.
2. **Context line:** ask Claude to quote any line containing "Skaldsaga" from its startup context. Compare it with the table above.
3. **No stray root project:** `ls -d /home/claude/.harness 2>&1`. Expect "No such file".
4. **Debug output:** ask whether any hook stderr is visible. Then run the hook by hand with `cwd` set to `pwd`, using the plugin found with `ls -d /root/.claude/plugins/*/*/skaldsaga`.
5. **`locate`:** run it from `pwd`.
6. **Nothing written:** `git status --short`, and check that `story/.harness/meter.json` is absent (one-level-down branch only).
7. **The skill (one-level-down branch only):** type `/skaldsaga`. It should find `story/` without asking for a path, report 0.3.1, and say the hook ran.

**Pass criteria:**
- The one-level-down branch shows the one-level-down line at startup, not just when run by hand.
- The empty branch shows nothing.
- In both, there's no `/home/claude/.harness` and nothing is written.
